# 词穹 V2.0 · Phase 0 项目审计

审计基线：`d7c73be`（EdgeOne 正式部署准备版）  
V2 开发分支：`v2-development`  
审计日期：2026-10-15

## 结论

当前项目可以继续采用纯静态 React 应用架构，不需要数据库或服务端即可完成 V2.0 的主体功能。64 个 List 和现有学习记录格式可以保留，但状态模型必须先做版本化迁移，才能可靠支持日历、学习时长、每日统计和断点续学。

V2.0 不应直接在现有单文件组件上继续堆叠功能。现有 `app/page.tsx` 同时承担加载、排程、学习、复习、打卡、导入导出和全部页面渲染，后续应拆分为数据层、调度层、统计层与页面组件，同时保持旧存储键可迁移。

## 技术与部署

- React 19.2.6、TypeScript 5.9.3、Vite 8.0.13、Tailwind CSS 4.2.1。
- EdgeOne 使用 `npm run build:edgeone`，输出目录为 `dist-edgeone/`。
- `edgeone.json` 指定 Node.js 22.17.1、`npm ci` 和纯静态输出。
- 运行时没有数据库、API、账号系统或环境变量。
- 页面仅请求同源 `vocab.json`；字体、图标和分享图均为本地资源。
- 发音使用浏览器 Web Speech API，音色与可用性由设备决定。
- 完整源码保存在 GitHub `edgeone-production` 分支；原 `main` 静态版本未覆盖。

## 词库核验

- List 数量：64，编号连续为 1–64。
- 词条数量：3,693。
- 每个 List：最少 16 条，最多 73 条。
- 字段：`id`、`order`、`word`、`definition`、`phonetic`、`list`。
- `id` 无重复；所有词条都有英文单词和中文释义。
- 2 条词缺少音标。
- 按英文拼写统计有 101 个重复项；可能是不同 List 的合理重复，V2 不自动去重。
- 词库没有例句、例句翻译、搭配、派生词和词性字段，V2 不会伪造这些内容。

## 当前学习与复习逻辑

- 学习模式：看词辨义、看义回想、听音拼写。
- 今日计划：三轮依次为认识与听音、四选一辨义、听音拼写。
- 基础间隔：1、3、7、15、30、60 天。
- `again`：阶段归零，10 分钟后复习。
- `hard`：至少阶段 1，次日复习。
- `known`：阶段加一，进入下一间隔。
- 到期任务通过 `next <= 当天日期/当前时间` 判断。

### 已识别问题

1. 日期函数使用 UTC 的 `toISOString()`，可能在中国时区午夜前后归档到错误日期。
2. 第 1、2 轮会覆盖同一个词条的 `rating`，最终统计不能准确表达每轮表现。
3. `known` 一次即可推进阶段；缺少独立、可测试的调度函数和答题历史。
4. 复习完成次数、正确率、用时、逾期数量没有独立记录。
5. 计划只按“剩余单词 ÷ 剩余天数”计算，没有每日时间、每周天数或复习负载。
6. 当前单词序号和未完成会话没有持久化，刷新后无法精确续学。
7. 今日计划缓存按日期建立，但缺少版本和过期清理策略。

## 当前数据存储

全部数据保存在 `localStorage`：

- `ielts-vocab-records`：逐词学习状态、收藏、阶段、下次复习日期与当天轮次。
- `ielts-exam-date`：考试日期。
- `ielts-plan-YYYY-MM-DD`：当天计划词条 ID。
- `ielts-checkins`：每日打卡摘要。

### 数据安全问题

1. 没有总数据结构版本号。
2. 写入没有统一异常处理，存储空间不足时可能静默失败。
3. 导出只包含 `records`，不包含考试日期、计划和打卡。
4. 导入只做 JSON 解析，不校验结构，也没有合并/覆盖确认。
5. 打卡只有完成数量、掌握数量和强化数量，无法支撑 V2 日历要求的正确率、复习量和学习时长。
6. 仅凭当前记录难以可靠避免重复统计学习次数。

V2 将引入带 `schemaVersion` 的统一快照，并在首次启动时读取上述旧键、无损迁移、保留原键作为回滚备份。

## UI 与响应式

- 当前主界面为单页模式切换，没有真正的首页、记录页和日历页信息架构。
- 已具备桌面和 `800px` 以下移动样式，但没有针对 375、390、430、768、1024、1440px 的自动化验收。
- CSS 在一个文件中多次覆盖相同变量和组件，存在历史主题叠加，维护成本高。
- 当前系统字体已符合 iOS 风格，但颜色、圆角和布局尚未达到 V2 的冰蓝、自然景观和 Bento 设计规范。
- 已支持 `prefers-reduced-motion`。

## 测试现状

- 现有测试仍是初始模板的 loading skeleton 测试，与当前产品不匹配。
- 没有复习调度、日期、数据迁移、统计、导入校验或交互测试。
- V2 必须先建立纯函数单元测试，再添加关键浏览器流程测试。

## 资源与待补材料

- 当前仓库没有 V2 指令提到的“第二张雪山湖泊原图”。
- 在获得原图前可以完成数据架构、组件系统和页面结构，但 Phase 2 最终背景优化需要用户提供原始图片。
- 现有 `og.png` 约 2 MB，后续需要压缩；不能把它当作雪山背景替代品。

## 主要风险

- 完整词书公开发布需要确认版权或授权。
- 浏览器发音在不同国产浏览器上的音色和兼容性不完全一致。
- `localStorage` 无法跨域自动迁移，旧站数据需要导出后导入新域名。
- 无账号系统时无法实现真正的跨设备自动同步。
- 中国大陆节点及 `ciqiong.com` 的实际接入可能需要 ICP 备案；香港测试节点不能等同于大陆稳定访问。
